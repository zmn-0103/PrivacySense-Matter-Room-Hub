# OTA 安全边界

## 1. 定位

本文档定义首版 OTA 功能的最低安全边界。首版 OTA 目标是**设计评审或最小可验证实现**，不宣称产品级 A/B 回滚能力。所有安全要求在此提前冻结，避免后续变成只验证"下载成功"。

## 2. 镜像来源

| 要求 | 说明 |
|---|---|---|
| 来源 URL | HTTPS，证书由 ESP-IDF `esp_crt_bundle` 验证（尚未实现） |
| 证书锁定 | 首版使用 ESP-IDF 内置 CA 证书包；不实现自定义证书锁定（尚未实现） |
| URL 来源 | 存储在 NVS 中，通过 BLE commissioning 或 Matter 写入（尚未实现） |
| URL 验证 | 必须以 `https://` 开头；不接受 `http://`（尚未实现） |
| 镜像格式 | ESP-IDF OTA 镜像格式（含镜像头和签名区） |
| OTA 流程 | **未定** — 首版暂未选择 Matter OTA Requestor 或自定义 HTTPS OTA；需在 Matter 集成阶段重新评估 |

> **现阶段状态（2026-07-19）**：分区表（OTA A/B + otadata）和 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` 已配置，但 OTA 下载、镜像确认、版本判断和 `esp_ota_mark_app_valid_cancel_rollback()` 均未实现。以下要求为规划草案，状态标注为"尚未实现"的项待 Builder AI 实现后逐一勾销。
>
> **重要**：
> - 镜像自带 SHA-256 只能证明完整性，不能证明发布者身份。
> - 首版应明确选择 Matter OTA Requestor 或自定义 HTTPS OTA，不要混合两套流程。
> - 官方 Matter OTA 使用 `CONFIG_ENABLE_OTA_REQUESTOR`，由 Matter 控制器触发 OTA 请求。
> - 详见 [ESP-Matter OTA 文档](https://docs.espressif.com/projects/esp-matter/en/latest/esp32/developing.html#ota)。

## 3. 完整性校验

| 校验项 | 方式 | 失败处理 |
|---|---|---|
| SHA-256 哈希 | 下载完成后计算镜像 SHA-256，与镜像头中的哈希比对 | 不匹配 → 丢弃镜像，记录错误，不切换分区 |
| 镜像头校验 | 检查 magic byte、segment 数量、入口地址 | 不匹配 → 丢弃镜像 |
| Flash 写入校验 | 写入后回读关键区域验证 | 不匹配 → 标记分区无效 |

> **已知限制**：
> - SHA-256 只能证明镜像完整性（未被篡改），不能证明发布者身份（无签名验证）。
> - 首版不实现镜像签名验证（需要 Secure Boot V2 配置），但在文档中标注为已知限制。
> - 后续启用 Secure Boot 后可增加签名验证。

## 4. 版本策略

| 规则 | 说明 |
|---|---|
| 版本号格式 | Semantic Versioning: `MAJOR.MINOR.PATCH`（如 `1.0.0`） |
| 版本比较 | 新镜像版本必须 > 当前版本，否则拒绝 |
| 版本来源 | 镜像头中的 `app_desc.app_version` 字段 |
| 降级保护 | 不接受版本号 ≤ 当前的镜像（防回滚） |
| 版本冲突 | 如果镜像未包含版本号或格式无效 → 拒绝 |

## 5. 分区与断电行为

### 5.1 分区方案

```text
Partition Table Draft (16 MB Flash, 2026-07-17 已实机确认):
├─ nvs         (32 KB)     — 配置存储
├─ otadata     (8 KB)      — OTA 分区选择
├─ phy_init    (4 KB)      — PHY 初始化数据
├─ ota_0       (5 MB)      — OTA 分区 A
├─ ota_1       (5 MB)      — OTA 分区 B
└─ coredump    (64 KB)     — Core dump 存储
   remaining              — 预留本地存储/分区对齐，最终由 partitions.csv 冻结
```

> 2026-07-17 已通过 `esptool.py --chip esp32c6 --port /dev/ttyUSB0 flash_id` 确认 16 MB Flash。两个 OTA 槽位必须等大，具体 offset 和最终余量仍需在首次项目 Matter 构建后根据镜像尺寸和 `partitions.csv` 校验。

### 5.2 断电行为

| 断电时机 | 行为 |
|---|---|
| 下载过程中 | otadata 未更新，下次启动仍从原分区启动，无影响 |
| 写入 Flash 过程中 | otadata 未更新，下次启动仍从原分区启动，写入不完整的分区被忽略 |
| otadata 更新后、首次启动新镜像前 | 下次启动尝试新分区，如果新镜像无法启动 → 看门狗复位后回滚到原分区 |
| 新镜像启动后、确认前 | 新镜像运行，但标记为 `unverified`；看门狗复位后可能回滚到原分区 |

### 5.3 镜像确认流程

1. 新镜像首次启动 → 运行 `app_desc` 中的初始化代码。
2. 初始化成功 → 调用 `esp_ota_mark_app_valid_cancel_rollback()` 标记为有效。
3. 初始化失败或看门狗超时 → 下次启动 Bootloader 自动回滚到上一个有效分区。
4. 回滚后 → RGB 黄色常亮 3 s 表示发生了 OTA 回滚，记录 `reset_reason` 包含 OTA rollback 信息。

### 5.4 回滚限制

| 项 | 说明 |
|---|---|
| 回滚次数 | ESP-IDF 支持自动回滚 1 次（到上一个有效分区） |
| 不支持多版本回滚 | 只保留 2 个分区（A/B），无法回滚到更早版本 |
| 用户告知 | 发生回滚时，RGB 黄色常亮 + Matter 上报自定义事件（首版可选） |
| 已知限制 | 如果新镜像能启动但功能异常（如 Wi-Fi 无法连接），不会自动回滚——只有启动失败或看门狗超时才触发回滚 |

## 6. 下载过程约束

| 约束 | 值 | 说明 |
|---|---|---|
| 下载超时 | 10 min | 超时后中止下载，不切换分区 |
| 单次写入缓冲区 | 4 KB | 流式写入，不全量缓存到 RAM |
| 最大镜像大小 | 5 MB（草案） | 受单个 OTA 槽位限制；首次构建后复核并保留增长余量 |
| 断点续传 | 首版不支持 | 超时或中断需从头下载 |
| 下载中行为 | 状态机正常运行 | 下载在 `config_task` 或独立 `ota_task` 中执行，不阻塞状态机 |
| 下载中 RGB | 紫色慢闪 (0.5 Hz) | 表示正在下载 OTA 镜像 |

## 7. 触发方式

| 方式 | 说明 | 首版支持 |
|---|---|---|
| Matter OTA Cluster | Matter 标准的 OTA 请求/通知流程 | 可选（视控制器支持） |
| BLE 命令 | BLE commissioning 期间下发 OTA URL | 否（BLE 仅用于 commissioning） |
| 本地按键触发 | 双击按键检查更新 | 否（首版不做） |
| 定时检查 | 定期从配置的 URL 检查更新 | 否（首版不做） |

> **现阶段（2026-07-19）**：首版 OTA 尚未实现。上述所有触发方式均为规划。A/B 分区和 otadata 已配置，但 Matter OTA Requestor、HTTPS 下载客户端、版本判断和镜像确认流程均未实现。以下各节为设计草案，待 Builder AI 在 Matter 集成阶段实现。当前不可声称 OTA 已实现。

## 8. 不做项与已知风险

| 不做项 | 风险 | 缓解 |
|---|---|---|
| 签名验证 | 镜像可能被篡改 | 首版使用 HTTPS 传输 + SHA-256 校验；后续启用 Secure Boot V2 |
| 断点续传 | 大镜像下载中断需从头开始 | 限制镜像大小；10 min 超时 |
| 多版本回滚 | 只能回滚到上一个版本 | 文档明确告知用户；A/B 分区是 ESP-IDF 标准 |
| 自动更新 | 用户可能错过安全补丁 | 首版定位为原型项目，不做自动更新 |
| OTA 过程中 Wi-Fi 断开 | 下载中断 | 下载超时处理；不切换分区；下次可重新触发 |

## 9. 验证清单

OTA 实现后必须验证以下场景：

- [ ] 正常下载并写入新镜像 → 重启后运行新版本
- [ ] 下载过程中断电 → 重启后仍运行旧版本
- [ ] 写入完成后、otadata 更新前断电 → 重启后仍运行旧版本
- [ ] 新镜像启动失败（故意烧录无效镜像）→ 自动回滚到旧版本
- [ ] 新镜像启动成功但看门狗超时 → 自动回滚到旧版本
- [ ] 版本号 ≤ 当前版本 → 拒绝下载
- [ ] SHA-256 不匹配 → 拒绝写入
- [ ] 下载超时 → 中止下载，不切换分区
- [ ] 回滚后 RGB 显示黄色常亮告知
